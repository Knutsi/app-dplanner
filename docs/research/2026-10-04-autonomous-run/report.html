An autonomous run, end to end

One Claude Code session directed 20 step agents and 3 Codex reviewers through a 26-step DPlanner plan. The run started from an empty feature branch and ended with a reviewed PR into main. It doubled as a field test of autonomous execution: what worked, what broke, and what a daemon would need.

1Outcome

In short

It worked, with a director. Every work step merged into refactor/arch-revision and was verified on the integrated branch. Codex approved the landing (PR #221) in round 2. What remains is Knut's S23: test the branch, then merge.

  • Correctness: two-writer file safety, all-or-nothing commands with undo that refuses a foreign value, unknown statuses never due, ended claims stay ended.
  • The pilot: planning/ owns status as an Enum (mypy rejects literal comparisons), and Set Status is one workflow under the context system. The window and the CLI now agree on all four rules (before, the window enforced 1 of 4). Architecture tests enforce the cross-module surface, an acyclic graph, ceilings and pinned stored ids.
  • The composition root: kinds, estimates, schedule, briefing (a headless agent_briefing package), branch planning, coverage, the ledger and the headless due decision with launch intents all moved to their owners. 4,923 → 3,551 lines.
  • Names: canvas, project_archive + steps/cli.py, agent_launch, agent_usage, status_board, schedule, and file roles enforced by a test.
  • Docs: ARCHITECTURE.md went from 9,103 lines to a 171-line index over area files plus a dated decisions.md. NOTES-FOR-APPFRAME.md is now organised per file, and CLAUDE.md went from 32.7 KB to 23.4 KB.

2How it was run

In short

No CLI verb launches an agent, and auto-launch never fires for plain links, so the director rebuilt Run Agent by hand: worktree, briefing, herdr tab, in-progress status. A watcher woke it on blocked or finished agents. Every plan was approved by reading it, every PR reviewed and merged, and every merge verified.

5What it taught

In short

Five lessons, ranked. The first is about the architecture itself. The rest are about running agents unattended.

  1. The effect boundary is the hard part of "units of work". Saving before the side effect (releasing a claim, dropping a launch intent) failed three review rounds in a row: Codex on S8, then R26 rounds 1 and 2. Each fix opened a narrower case. The pattern is right, but it needs one owed-effects mechanism shared by the CLI, the window and auto-launch, tested at its boundary.
  2. Cross-vendor review earns its cost. Codex found 14 real issues the step agents, their tests and the director missed, most with a failing reproduction. When the director stood in for one round, it missed a hole that R26 later found.
  3. Parallel plans against shared code overlap reliably. Two collisions were caught only by reading plans side by side, and four merges conflicted anyway.
  4. Decisions made from a report are proposals. Twice the rename list met coupling the report couldn't see. The agents' questions led to better calls, recorded as amending notes.
  5. Unattended means bounded. One hung suite cost 7.5 hours. Memory and /tmp (RAM-backed here) were the binding resources, not cores, and model usage limits stopped the reviewer twice.

6Bugs found

In short

Found by running the plan. The worst: step keys resolve across the library (a command wrote to another project), the window segfaulted in table sizing under load, and the test suite could launch real agents.

  1. Step keys and titles resolve across the library; review set R26 changed another project's step (reverted).
  2. The window segfaulted in rich_row_height ← table.sizeHint under load (crash log).
  3. A stub in test_sync missed after a refactor, and the suite opened real Ghostty windows running claude.
  4. status set … done on a step that is already done is refused from an agent shell, with a misleading message.
  5. A stray /tmp/.dplanner from test_move_plan broke another test's upward walk.
  6. Two render scripts had been silently broken for weeks (now on a ratchet).
  7. The focus-dependent double-click tests in test_testing.py failed in 5 of 16 parallel runs.

Reproductions are in bugs.md.

7Friction

In short

DPlanner lacks a headless launch, and its own herdr row opens a workspace per run. herdr's "idle" doesn't mean "finished". Codex prompts per command and runs into usage limits.

  • DPlanner:
    • No agent run verb; the director forgot in-progress, and missed that a landing works on the feature branch itself.
    • Auto-launch ignores plain links.
    • The standing instruction reaches review and landing briefings, where it doesn't apply.
    • The PR refresher marks a step done before it has been verified.
  • herdr:
    • "Done" while waiting on its own shell or subagents.
    • A plan approval sometimes reads as done.
    • No scrollback while blocked.
  • Codex: 21 sandbox prompts; the plan repo is outside its writable roots; two usage limits.

Details are in ergonomics.md.

9What should change

In short

In order of value. The first two would have removed most of the director's hand-work and all three review rounds on the same seam.

  1. dplanner agent run <step>: a headless launch that sets the worktree, briefing, in-progress and run intent. It's also the daemon's door.
  2. One owed-effects mechanism after the save, shared by the CLI, the window and auto-launch, tested at its boundary.
  3. A spawn guard in the test session.
  4. Timeouts and a heartbeat that survive the night.
  5. Overlap warnings when two in-flight steps plan to touch the same symbol.
  6. One inbox for every agent's questions (Knut's idea), fed by agent-state and the multiplexer's blocked state, shown in the window and future factory views.
  7. Project-scoped keys.
  8. DPlanner's herdr row should open one workspace per project with a tab per run; Codex reviewers launched with the plan repo and test commands pre-allowed.
