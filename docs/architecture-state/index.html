The two primary questions
Do the modules still remain fully separate?
Yes. holds

Not one of the 46 packages under modules/ imports another, and the rule is enforced by a test that parses every file's imports with ast (type-checking imports included). Framework, domain, core and CLI never reach up into a module. The only leaks are three places where a module names another module's id as a string, and one of them is a deliberate migration.

How do they integrate or share functionality?
Through five channels, and one room. crowded

Framework registries, typed callbacks on each module's Deps, Qt-free exports collected into tuples, derivations in domain/ handed functions instead of schemas, and a shared on-disk vocabulary. Every one of those channels is wired in one file — modules/__init__.py, now 2,838 lines — and that file has quietly become the largest module in the application.

The short version: the boundary the architecture promised is intact, and the cost of keeping it has been paid in a single place. The entropy is concentrated, which is the good kind — it is findable, and most of it comes out with one refactor of the composition root and one deletion.

Section 3

How modules integrate

Summary

A module never asks another module anything. It either registers into a framework registry that a host reads, declares a typed callback on its own Deps that the root fills in, or exports a Qt-free value the root collects into a tuple. Facts several modules need are derived in domain/ from functions handed in, never from schemas. The design is sound and consistently applied; the pressure shows up as the same fact being handed to many modules under more than one name, and as logic that has no module to live in accumulating in the root.

The five channels

1 · Framework registries

A module registers a thing; a host it has never heard of renders it. Eleven registries and services, three of which are the same InspectorSectionRegistry type instantiated for three hosts (step tabs, Details blocks, project cards).

deps.actions.register · deps.tabs.register_factory · deps.segments · deps.panels · deps.sections · deps.cards · deps.settings_sections

2 · Typed callbacks on Deps

A module names the fact it needs as a function on its own frozen dataclass; the root closes it over another module's headless half. 79 of the 342 Deps fields are such callbacks.

status_for · days_for · step_key · milestone_color · facts_for · pick_assets · compile_with_agent

3 · Qt-free collectors

A module exports a value from a file the architecture test knows by name; the root assembles the tuple both surfaces read. Ten collectors, from 14 aspect specs to 32 CLI command modules.

aspect_specs · default_cli_commands · _report_sources · _lint_checks · _machine_checks · _asset_sources · _paste_policies · _source_kinds · agent_harnesses · theme_providers

4 · Domain derivations

The order, the schedule, a collector's cone, the frontier, the asset catalogue: computed in domain/ from functions handed in, so the owner of a fact keeps its shape. The same seam as a Deps callback, one level down.

schedule.parallel_finish(days_for=…) · scope.cone(stops_at=…) · progression(status_for=…)

5 · Shared vocabulary on disk

A module owns a namespace in module_data, module_text and a file area, versioned by itself. The shelf, the formats list and the migration pass are the framework's; no module reads another's key except through channel 2.

node.module_data[MODULE_ID] · store.files(node, MODULE_ID) · modules/shelf.json · Takeover

+ · Protocols and small contracts

Where a callback is not enough, a consumer-owned Protocol or a small record: SidePanel, ScopeKind, PastePolicy, AgentHarness, ThemeProvider, SourceKind, ReportSource, RepositoryServices. This is the pattern working best.

Where the boundary is thin

The import rule cannot see a string. Three places name another module's id as a literal:

  • modules/docs/activity.py maps "feature", "step_milestone" and "step_check" to glyph names in _glyph_for — a copy of what _step_type_icons and theme/icons.py already agree on. copy
  • modules/feature/migrate.py writes into "step_description"'s namespace when it absorbs the old catalogue — a documented one-way migration, and the least bad way to do one. deliberate
  • modules/step_order/view.py keeps a KIND_FEATURE = "feature", and project_assets matches a role against "spec" — vocabulary, not a read of the other module's data. minor
Section 4

Where the entropy sits

Summary

Moderate, and concentrated. The module boundary is clean, the tests are green bar one font-metric assertion, lint and strict typing pass on both platforms, and there is not a single TODO in the tree. What has accumulated is (1) a composition root that does work of its own, (2) a subsystem with no caller, (3) a handful of facts with more than one home, (4) names that stopped describing their package, and (5) a rulebook large enough to be an entropy source in itself.

high

The composition root is a module in disguise

src/dplanner/modules/__init__.py · 2,838 lines · 71 commits

default_modules() is one function of 1,529 lines constructing 41 Deps records with 56 lambdas and 256 imports from module packages. That much is wiring and belongs here. Below it sit roughly 550 lines that are not wiring: the whole agent briefing assembler (_briefing_sections, _briefing_instruction, _agent_preamble, _agent_epilogue, _plan_whereabouts), step identity (_step_key, _step_kind, _step_type_icons, _ticket_key, _run_name), the milestone and step statistics, and the coverage trace assembly (103 lines). Each is genuinely cross-module, which is why it landed here, but the file has no tests of its own, no docstring at the top saying what it now contains, and every feature edits it — the largest wiring blocks are projects (115 lines), reporting (87) and step_properties (77).

The architecture already has the answer for cross-module verbs: cli/lint.py, cli/scopes.py and cli/report/ own their shapes and are fed by the root. The briefing and step identity are the same kind of thing without that home.

medium

The LLM service has no caller

modules/llm, llm_anthropic, llm_openai (612 lines) · framework/llm.py, llm_service.py · modules/debug/view.py

Since compiling documentation moved to a launched agent, nothing in a feature calls LLMService.complete(). The only reader is the Debug menu's LLM call log, which logs calls nobody makes. That is three modules, two framework files, a settings page, a provider registry and a keychain secret — about a thousand lines that must still pass type checking, be listed in the Settings dialog, and be explained to the next developer. The debug package's docstring still says it is "currently the LLM call log".

medium

Step identity has three homes and two names

modules/__init__.py::_step_type_icons · modules/docs/activity.py::_glyph_for · Deps fields step_key / key_of, kind_of

The rule in CLAUDE.md is one rule, four readers: the letter of a step's key follows its kind, computed in _step_key. The glyph for a kind is the same question, and the docs tab answers it with a private dictionary keyed on other modules' ids rather than through the step_icons callback step_order already receives. Meanwhile reporting takes the key as key_of and the kind as kind_of, where every other module says step_key. Two spellings of one seam is how a reader concludes they are two seams.

medium

Names that stopped describing their package

modules/step_agent_instruction · modules/debug · modules/feature · modules/step_order

step_agent_instruction is 4,348 lines across eleven files — the launcher, the terminal table, launch profiles, the run dialog, the detect dialog, the settings page and the 23-field Deps with ten callbacks. The instruction aspect is one file of it. The package is the agent launch module, and a developer looking for "where does Run Agent live" will not open it first. Three docstrings are also behind the code: debug ("currently the LLM call log"; it holds the design example, the telemetry view and the Windows check), feature ("catalogued beside it"; the catalogue was removed — a feature is a step) and step_order ("what can be started now"; that moved to the Ready-to-start board).

low

The project start date has a split owner

modules/estimation/schedule.py (stores it) · modules/time_estimates (edits it) · domain/schedule.py

CLAUDE.md says the Time tab "owns the start date", but the value is read and written by estimation/schedule.py under estimation's namespace, and the root hands start_of/set_start across. It works, and the seam is typed — but a developer following the rulebook will look in the wrong package, and two files called schedule.py beside a third in domain/ do not help. Either move the date with a Takeover or write down why it stays.

low

The rulebook is large enough to drift

CLAUDE.md 1,781 lines / 118 rule bullets · ARCHITECTURE.md 5,542 lines / 54 sections · README.md layout map

The documentation is a real asset — it is why the boundary has held through 288 commits in twelve days. But CLAUDE.md's Mechanical facts list is now 118 bullets of prose, most of them a paragraph, and it is read in full by every agent on every task. The README's layout map is behind by four packages (docs, llm_anthropic, step_description, taskcenter), and nothing checks it. A map nobody verifies is the first thing to stop being true.

fine

What looked like entropy and is not

Two packages carrying a second module class (DocsCompiledModule, ProgressHistoryModule) are documented and each declares only a format. Registration order carrying meaning is documented at every constrained position. The spec_*, agent_* and theme_* families are the cleanest pattern in the tree. Nine settings_page.py files and twelve report.py files are repetition by name, which is the convention working, not a duplicate.

Section 6

What to do about it

Summary

Ranked by entropy removed per hour. The first two are the ones that matter; the rest are an afternoon each and mostly renames.

  1. Make the composition root a package. Keep modules/__init__.py as the one importer of everything, but let it be a thin façade over modules/_root/: wiring.py (default_modules), collectors.py (aspects, CLI, report, lint, checks, assets, paste, sources, harnesses, themes), briefing.py and identity.py (step key, kind, icons, stats). Extend rule 4 in tests/test_architecture.py so that package is the only other place allowed to import modules, and give identity.py and briefing.py tests of their own. No module changes; the seams stay exactly where they are.
  2. Retire the LLM service, or give it a caller. If no feature is coming back to it, delete llm, llm_anthropic, llm_openai, framework/llm.py, framework/llm_service.py, the LLMProviderRegistry field on AppServices and Debug's call log, and record the removal in NOTES-FOR-APPFRAME.md. About a thousand lines and one keychain entry go, and the Settings dialog loses three pages that configure nothing.
  3. One name per seam. Rename ReportingDeps.key_of → step_key and kind_of → step_kind; hand docs the step_icons callback and delete _glyph_for's dictionary.
  4. Rename step_agent_instruction to what it is — agent_launch, keeping the aspect id on disk through the existing Takeover mechanism so no project changes — and refresh the four stale docstrings (debug, feature, step_order, and the renamed package).
  5. Settle the start date. Move it into time_estimates with a Takeover converter, or add one sentence to the rule in CLAUDE.md saying it lives in estimation and why.
  6. Make the layout map a test. A ten-line test that every directory under modules/ appears in README's Layout section; then consider moving the Mechanical facts bullets that are about one module into that module's docstring, with CLAUDE.md keeping the cross-cutting rules only.
Appendix

Method

Every number on this page was measured on commit 8e36a61 and can be re-run. Line counts are wc -l over *.py; churn is git log --oneline -- <path> | wc -l; Deps fields were read with ast from each module.py (and coverage/activity.py, where that module keeps its record); a field counts as a callback when its annotation contains Callable. Root lines per module is the distance in default_modules() from the previous *Deps( to that module's. Cross-module imports were checked both with the suite's own test_architecture.py and with an independent grep; string coupling was found by searching every module for another module's MODULE_ID literal and reading each hit in context.

QT_QPA_PLATFORM=offscreen uv run pytest -q     # 2969 passed, 26 skipped, 1 failed (font metrics)
uv run ruff check                               # clean
uv run mypy                                     # clean, 605 files
uv run mypy --platform win32                    # clean, 605 files
grep -rn "from dplanner.modules\." src/dplanner/modules --include=*.py \
  | grep -v "modules/__init__.py"               # 0 cross-package hits

What this report does not measure: runtime behaviour, the size of the per-user data formats, and whether the rules in CLAUDE.md are each still followed — only whether the tree still has the shape they describe.
