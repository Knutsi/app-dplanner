## How to read it

- **Overview** answers "is it on track": how much has landed, when the work lands with the
  team it is planned for, and how that landing moved since the plan was recorded. The chart
  draws the plan as it stands (solid), the plan as it was on the basis day (dashed) and what
  actually landed (ink). A milestone stands on it as a named hairline where the plan lands it.
- **Plan** is the work as a graph. A card is a step; an arrow means the step at its head
  waits for the one at its tail; a dashed line is a plain relation. The strip on a card's left
  carries its key and is washed by status — blue in progress, red blocked, green done. Click a
  card, a row or a milestone anywhere on the page to open it.
- **Timeline** is the milestones in sequence, each bar from its start to where the plan lands
  it, filled as far as its work has landed; a small triangle marks a date somebody set. The
  staffing table says when the same work would land with a different team.
- **Order** is one order the steps can be done in, with the estimated days accumulating along
  the longest chain. **Steps** lists everything; filter it, or pick a status.
- **Decisions** are what the team settled along the way, newest last.

## What DPlanner is

DPlanner is a development planner: it plans *projects* — each one a directory of plain files
inside a git repository — as a graph of steps carrying estimates, statuses, tests,
documentation and the record of what was decided. It is driven by people through a desktop
window and by coding agents through a command line, and both write the same files, so a
plan an agent updates from a terminal is the plan a person sees in the window a moment later.

## Getting DPlanner

DPlanner is a Python application. With [uv](https://docs.astral.sh/uv/) installed:

```
uv tool install dplanner
dplanner install all         # the applications-menu launcher and the agent skill too
dpw                          # or open the window straight away
```

`dplanner --help` lists the command line, and `dplanner install status` says what this
machine has — the command, the launcher and the skill that teaches a coding agent the tool.
